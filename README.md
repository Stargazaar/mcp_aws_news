# SG Healthcare News MCP Server on AWS EC2

A learning project that deploys a Python [MCP](https://modelcontextprotocol.io/) server onto an AWS EC2 free-tier instance. Claude Desktop connects to the server and can fetch Singapore healthcare news headlines and send email digests — all via natural language.

## What you will learn

| Concept | Where you see it |
|---|---|
| AWS EC2 fundamentals | Launch, key pairs, security groups, SSH |
| Linux service management | systemd unit file, journalctl logs |
| Model Context Protocol (MCP) | FastMCP, SSE transport, tool definitions |
| RSS feed parsing | `feedparser`, Google News RSS |
| SQLite caching | TTL cache, cache invalidation |
| Gmail SMTP | App Passwords, `smtplib`, HTML email |
| Python project structure | Modules, `.env`, `requirements.txt` |

## Part 2 — Launch EC2 instance

### 2.1 Open the EC2 console

1. Log in to [console.aws.amazon.com](https://console.aws.amazon.com)
2. Top-right region selector → choose **Asia Pacific (Singapore) `ap-southeast-1`**
   *(closest to you, makes sense for an SG news project)*
3. Search bar → **EC2** → click **Launch instance**

### 2.2 Configure the instance

| Setting | Value |
|---|---|
| Name | `sg-health-news-mcp` |
| AMI | **Ubuntu Server 24.04 LTS** (Free tier eligible) |
| Architecture | 64-bit (x86) |
| Instance type | **t2.micro** (Free tier: 750 hrs/month for 12 months) |
| Key pair | Create new → see 2.3 below |
| Storage | 8 GiB gp3 (free tier includes 30 GiB) |

### 2.3 Create a key pair

1. Click **Create new key pair**
2. Name: `sg-health-news-key`
3. Key pair type: **RSA**
4. Private key file format: **.pem** (works with Windows OpenSSH)
5. Click **Create key pair** — a `.pem` file downloads automatically
6. Save it somewhere permanent, e.g. `%USERPROFILE%\.ssh\sg-health-news-key.pem`

### 2.4 Configure security group

Click **Edit** next to Network settings, then add these inbound rules:

| Type | Port | Source | Purpose |
|---|---|---|---|
| SSH | 22 | My IP | SSH from your current network only |
| Custom TCP | 8000 | My IP | MCP server (Claude Desktop connects here) |

> **Security note**: Choose **My IP** as the source rather than `0.0.0.0/0`. If you switch
> networks (home ↔ office), edit the rules and pick **My IP** again. Port 8000 also requires
> a bearer token (`MCP_AUTH_TOKEN`, generated by `setup.sh`), so the server can't be used
> to send email from your Gmail account even if the port is reachable. Traffic is still plain
> HTTP, so the token is sent unencrypted; don't reuse it anywhere else.

### 2.5 Launch

Click **Launch instance**. Wait ~60 seconds. Note down the **Public IPv4 address** from the instance details page — you will need it in every step below.

## Part 3 — SSH into EC2 from Windows

### 3.1 Fix key file permissions (required on Windows)

Open **PowerShell** (not Command Prompt):

```powershell
$key = "$env:USERPROFILE\.ssh\sg-health-news-key.pem"
icacls $key /inheritance:r /grant:r "$($env:USERNAME):(R)"
```

Without this step, SSH refuses the key with a "bad permissions" error.

### 3.2 Connect

```powershell
ssh -i "$env:USERPROFILE\.ssh\sg-health-news-key.pem" ubuntu@YOUR_EC2_PUBLIC_IP
```

Replace `YOUR_EC2_PUBLIC_IP` with the actual IP from step 2.5.
Type `yes` when asked to confirm the fingerprint. You are now inside the EC2 instance.

## Part 4 — Deploy the server

### 4.1 Run the setup script

Inside the EC2 SSH session:

```bash
git clone https://github.com/YOUR_USERNAME/mcp_aws_news.git ~/mcp_aws_news
cd ~/mcp_aws_news
chmod +x setup.sh
./setup.sh
```

The script:
- Installs the system Python 3 and git
- Creates a Python virtual environment in `~/mcp_aws_news/venv/`
- Installs `requirements.txt`
- Generates `MCP_AUTH_TOKEN` in `.env` and prints it. Copy it for Part 5 (view it later
  with `grep MCP_AUTH_TOKEN ~/mcp_aws_news/.env`)
- Installs and enables the systemd service

### 4.2 Configure Gmail credentials

```bash
nano ~/mcp_aws_news/.env
```

Fill in:
```
GMAIL_USER=your.email@gmail.com
GMAIL_APP_PASSWORD=xxxx xxxx xxxx xxxx
```

**How to get a Gmail App Password:**
1. Go to [myaccount.google.com/security](https://myaccount.google.com/security)
2. Enable **2-Step Verification** if not already on
3. Go back to Security → scroll down to **App passwords**
4. App: **Mail** | Device: **Other** → name it `ec2-mcp` → click **Generate**
5. Copy the 16-character password into `.env`

Save with `Ctrl+O`, exit with `Ctrl+X`.

### 4.3 Restart the service

```bash
sudo systemctl restart sg-health-news
sudo systemctl status sg-health-news   # should show "active (running)"
```

### 4.4 Verify the server is up

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST http://localhost:8000/mcp
```

You should see `401`. That means the server is up and rejecting requests without the token.

### 4.5 Useful commands

```bash
# Live logs
sudo journalctl -u sg-health-news -f

# Restart after code changes
sudo systemctl restart sg-health-news

# Stop the service
sudo systemctl stop sg-health-news

# Check what port it is listening on
ss -tlnp | grep 8000
```

## Part 5 — Install and configure Claude Desktop

### 5.1 Install Claude Desktop

Download from [claude.ai/download](https://claude.ai/download) and install.

### 5.2 Find the real config path

The config location has moved between Claude Desktop versions, and stale copies can be left
behind in the old locations (`%APPDATA%\Claude\`, `%LOCALAPPDATA%\Claude\`,
`%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Roaming\Claude\`). Editing a stale copy does nothing.

**Reliable way:** Claude Desktop → **Settings → Developer → Edit Config**. That opens the file
the app actually reads. On recent Windows installs it is:
```
%LOCALAPPDATA%\Claude-Data\claude_<id>\claude_desktop_config.json
```

To check from PowerShell which one is current (the newest is usually it):
```powershell
Get-ChildItem $env:LOCALAPPDATA, $env:APPDATA -Recurse -Filter claude_desktop_config.json -ErrorAction SilentlyContinue |
  Sort-Object LastWriteTime -Descending | Select-Object LastWriteTime, FullName
```

### 5.3 Write the MCP config

Claude Desktop only supports **local stdio servers** via config — remote servers use `mcp-remote` as a local proxy.
You need `Node.js` installed (`node --version` should return a version number).

Open the config from step 5.2 in a text editor. **Don't overwrite the whole file**: it also
holds Claude Desktop's own `preferences`. Add or replace only the `mcpServers` entry
(replace the EC2 IP and token):

```json
  "mcpServers": {
    "sg-health-news": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://YOUR_EC2_PUBLIC_IP:8000/mcp", "--allow-http",
               "--header", "Authorization:${AUTH_HEADER}"],
      "env": {
        "NODE_OPTIONS": "--use-system-ca",
        "AUTH_HEADER": "Bearer YOUR_MCP_AUTH_TOKEN"
      }
    }
  },
```

> **Notes**:
> - `--allow-http` is required because mcp-remote blocks non-HTTPS URLs by default
> - `NODE_OPTIONS: --use-system-ca` is required on corporate/enterprise networks with SSL inspection
> - The transport is `streamable-http` and the endpoint is `/mcp` (not `/sse`)
> - The token goes in `env` (not directly in `args`) because Windows mangles spaces inside
>   `args`; `Authorization:${AUTH_HEADER}` deliberately has no space after the colon

### 5.4 Restart Claude Desktop

Fully quit from the system tray (right-click → Quit — closing the window is not enough).
Reopen it. After ~10 seconds, check **Settings → Developer** to confirm the server shows as connected.

**Troubleshooting** (logs: Settings → Developer → sg-health-news, or
`%LOCALAPPDATA%\Claude\logs\mcp-server-sg-health-news.log`):

| Log shows | Cause | Fix |
|---|---|---|
| No `Using custom headers: Authorization` line | Claude Desktop is reading a different config file | Use **Edit Config** (step 5.2) and edit that file |
| `Authentication required` **with** the custom headers line | Token doesn't match `.env` on EC2 | Re-copy it: `grep MCP_AUTH_TOKEN ~/mcp_aws_news/.env` |
| `Another instance is running the sign-in for this server` | Leftover `mcp-remote` process from a failed attempt | Quit Claude Desktop, end leftover `node.exe` processes in Task Manager, reopen |
| `Request timed out` / no response | Your public IP isn't allowed in the security group, or the instance is stopped | See Part 7 checklist |

## Part 7 — Cost control (important)

The t2.micro is free for **750 hours/month** on new accounts (12 months).
That is enough to run it 24/7, but here is how to stop it when not using it:

**Stop the instance** (data is preserved, no hourly charge):
1. EC2 Console → Instances → select your instance → Instance state → **Stop**

**Start it again — checklist.** Two different IPs can change:

1. **The EC2 IP changes on every stop/start.**
   - EC2 Console → Instance state → **Start**, then copy the new **Public IPv4 address**.
   - Update it in your SSH command and in the `http://...:8000/mcp` line of
     `claude_desktop_config.json` (step 5.2), then fully quit and reopen Claude Desktop.
2. **Your own public IP can change too** (different network, or an office network that rotates IPs).
   - Symptom: SSH or Claude Desktop times out even though the instance is running.
   - Check it with `curl.exe -s https://checkip.amazonaws.com`. If it isn't in the security group,
     go to **Edit inbound rules → Add rule → Source: My IP** for ports 22 and 8000.

**Fixed EC2 IP (optional):** Elastic IP → Allocate → Associate with your instance. Public IPv4
costs ~$0.005/hr (~$3.60/month) either way. An Elastic IP is also billed while the instance is
stopped, so it only makes sense if you keep the instance running.
Release it (Elastic IPs → Release) when you're done with the project.

## What MCP is (plain English)

Without MCP, Claude only knows what it was trained on — no live data, no external tools.

With MCP, Claude can call functions on your server **during a conversation**:

```
User:    "What are the latest SG healthcare headlines?"

Claude:  [calls get_headlines("singapore healthcare", weeks_back=2)]
         [receives structured list back from your EC2 server]
         [summarises and responds]

Claude:  "Here are the top headlines from the past 2 weeks: ..."
```

MCP standardises this with a JSON protocol over HTTP/SSE, so any MCP-compatible client
(Claude Desktop, Cursor, custom apps) can talk to any MCP server you write.
